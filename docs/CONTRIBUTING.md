# Contributing to EventScribe

## Branches

- `main` contains integrated work.
- Use `feature/<short-name>` for feature work.
- Use `fix/<short-name>` for bug fixes.
- Use the teammate-specific branches from `PRD.md` for the bounded contributor tasks.

## Pull-request workflow

1. Read the relevant task in `PRD.md`.
2. Create a branch from the latest `main`.
3. Make only the scoped change.
4. Run the relevant tests or checks.
5. Commit with a clear message.
6. Push the branch and open a pull request.
7. Describe what changed and how it was tested.

Akshansh is the final integration owner. Contributors should not rewrite unrelated files or change the core architecture without agreement.

## Commit rules

- Do not commit API keys, `.env` files, private documents, private photographs, or generated reports.
- Keep commits focused and explainable.
- Do not change commit authorship to make another person appear to have written work they did not write.
